## Why

ChatGPT Bot Kit has linked workflow tools but no accepted consumer policy or
activation checkpoint. Establish the requested AssuredLoop workflow before
product development starts, with review and acceptance recoverable from GitHub.

## What Changes

- Bind this consumer to `guwenqing/chatgpt-bot-kit`, native OpenSpec and Codex.
- Adopt the project choices in `.assuredloop/policy.md`, subject to owner approval.
- Initialize the selected `assuredloop-base@0.1.0` package and its seven skills.
- Preserve npm links while recording the exact selected package artifact and
  source revision; changed linked bytes require a reviewed binding update.
- Establish accepted bootstrap in `main`, then assess and deliver a separate
  activation checkpoint with real verification, review and authorization sources.

## Capabilities

### New Capabilities

None. This adopts existing workflow tooling and project policy; it does not add
application behavior. Framework contracts remain in the selected package.

### Modified Capabilities

None. Product requirements are not yet defined. This tooling-only change uses
native OpenSpec's `skip_specs: true` rather than inventing a product specification.

## Impact

Project workflow configuration, namespaced Codex skills, repository instructions,
GitHub category labels and Issue/PR evidence. No application runtime, business
code, CI enforcement, provider orchestration, registry publication or deployment
is introduced. The owner accepts the precise policy and authorizes its activation
after independent review; these decisions are distinct from installing files.
